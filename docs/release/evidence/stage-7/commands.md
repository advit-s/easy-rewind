Machine-local build files and terminal output are not durable release
evidence. Retained evidence must be redacted, checksum-bound, and exclude user
content, credentials, hostnames, runtime databases, quarantine manifests, and
private keys.

The normal CI jobs and retained non-release artifacts are:

| Job                  | Boundary                                                                                                                                     | Retained artifact                                         |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `quality`            | format, lint, secrets, hygiene, audit, workspace/containment/hygiene tests                                                                   | none                                                      |
| `backend`            | legacy-safe backend, contracts, migrations, domain, jobs, remote/import-export, sync, full backend                                           | none                                                      |
| `clients`            | Chrome, dashboard, mobile tests/typecheck/validation, extension package, Expo Android JS export, then generic content/secret/path inspection | `client-builds-non-release` plus client evidence (7 days) |
| `electron-package`   | desktop tests, package validation, native ABI, unsigned Windows build and inspection                                                         | `windows-unsigned-non-release` (3 days)                   |
| `artifact-checksums` | downloaded client/Windows inspection and deterministic SHA-256 evidence                                                                      | `artifact-checksums` (14 days)                            |

The manual release gate requires the exact checked-out commit, an opaque
provider-revocation reference and attestation SHA-256, and protected Windows
and Android signing secrets before release acceptance can start. Windows files
are accepted only when `Get-AuthenticodeSignature` reports `Valid`; the release
inspector rejects `UNSIGNED` names. No invocation or success of that gate is
claimed here.
